# 毛毛蟲賽車（caterpillar-race）

> **左右兩顆鍵，走線取勝。**
> 追尾立體視角的可愛賽車遊戲：八隻手繪毛毛蟲、二十張賽道、加速帶與道具、四段電腦對手，
> 以及最多六人同場的線上競速。整個專案**零依賴**，雙擊 `啟動遊戲.bat` 就能玩。

---

## 這款遊戲在玩什麼

平板和手機上毛毛蟲會自己一直往前爬，**不用管油門**，只要做三件事：左轉、右轉、用道具；
電腦上油門在你手上：按住上才會前進、放開會自己滑行停下來，下是煞車停住後慢慢倒退，左右轉向。

速度取決於你選的路線：直線穩定前進，過彎時提早轉向，踩到露珠加速帶或使用果汁道具可以短暫加速；
轉彎太晚、撞牆或跑到草地都會損失時間。起跑線由中央向兩側排開，開局先把毛毛蟲放在同一條線上。

第一名衝線之後開始**倒數 10 秒**，那是整場共用的倒數 —— 畫面上方一個大數字，每個人都看得到，每一秒有音效；
10 秒內沒衝線就算沒跑完，這一局也跟著結束。衝過終點線時畫面正中央會報名次，
收局後停一秒才切到結算。

這就是整個遊戲的取捨，也是為什麼主角是毛毛蟲而不是車。

## 怎麼跑起來

### 最快的方式

雙擊 **`啟動遊戲.bat`**（會自己找 Node，包含 nvm-windows 裝的版本），
瀏覽器會開 <http://localhost:3070>。

### 用命令列

```bash
npm start          # 開伺服器（單機 ＋ 線上都能玩）
npm test           # 規則核心單元測試
npm run verify     # 全部驗收（規則／賽道／道具／電腦對手／美術／音訊／流程／線上）
```

只想玩單機的話，直接用瀏覽器打開 `public/index.html` 也可以，不需要 Node。

### 線上對戰

- 2～6 人同一條賽道，觀戰席上限 20 人
- 席位滿了或對局進行中進來會**自動轉觀戰並告訴你**，不會默默把觀戰者當成玩家
- 房主使用獨立的「開始遊戲」按鈕；其他玩家都按準備後才可開跑
- 邀請連結有**範圍、有效期限（與房間同生命）與撤銷狀態**，房主可以隨時重發
- 房間左側是操作 Summary、左下是聊天室（有快捷短語與未讀數），賽道畫面盡可能大
- 對局中掉線會**幽靈化**（半透明、不擋路、位置保留），30 秒內重連可以回到原位；超時退賽
- 伺服器 30Hz 權威迴圈，前端做預測與平滑校正，誰贏誰輸一律以伺服器為準

## 立體感是怎麼做出來的

賽道不是平面色塊。光源固定在左上，每一張賽道都疊了四層：

1. **草地斷面**：跑道外圈一條深綠色帶，等於草皮被切開露出的側面
2. **草地上緣亮線**：斷面往光的方向推一點再描一次，像切口被照到
3. **路面內側投影**：把路面輪廓往光的反方向推去描粗線，再夾在路面裡 ——
   推出去的那半邊被夾掉，只剩「草牆投在路上」的那一半
4. **路面內側邊光**：同樣手法但往光的方向推，對面的斜坡受光

再加上彎道的紅白緣石、凹下去的泥巴水窪、有接地陰影與高光的石頭，
路面就會讀成「比草地低一階」。

### 起跑燈架

起跑用的是賽車的燈架，不是數字倒數：**一排三顆**紅燈一顆一顆亮起來，
三組全亮之後**同時熄滅**＝開跑。比數字好讀的地方在於「還剩多久」是一眼看得到的量，
不用讀字；而且熄燈是同時發生的，起跑時機很明確。

時間全部從 `Rules.C.COUNTDOWN` 推算（第 i 組在 `(i-1) * COUNTDOWN/3` 亮起），
倒數改長改短都不用動這段。三秒就是 0.0 / 1.0 / 2.0，一組一秒，
跟原本 3-2-1 的叫聲同步；最後留一秒「三組全紅」——
那段全紅是起跑燈的關鍵節奏，沒有的話最後一組一亮就熄，玩家反應不過來。

熄燈之後燈架還會留 0.7 秒（`CD_LIGHTS_OUT`）。相位一換就把燈架整個收走的話，
玩家看到的是「燈架消失」而不是「熄燈」，那個關鍵的一瞬間就沒了。

燈架掛在畫面上方的天空帶裡（地平線在畫面高度三分之一處，`Render.HORIZON`），
所以不會蓋到路面與毛毛蟲 —— 倒數的時候還是看得到自己在哪、前面是什麼路。
水平置中，左邊的資訊面板與右上的小地圖都不會被擋到。

燈架尺寸一律用 `vmin`，所以直向橫向、手機平板桌機共用同一組數字。
燈號對讀螢幕的人沒有語意，燈架標了 `aria-hidden`，另外用 `.cd-sr` 播報文字。

### 賽道機制

地形存在一張格子圖裡（`Tracks.SURFACE`，`Uint8Array`），物理一律查格子，
所以單機與線上跑的是同一套規則。

| 地形 | 速度 | 抓地力 | 手感 |
| --- | --- | --- | --- |
| 跑道 | 1.00 | 0.02 | — |
| 草地 | 0.65 | 0.10 | 慢，而且會滑 |
| 泥巴 | 0.45 | 0.03 | 最慢，但抓得住 |
| **水坑** | 0.62 | **0.30** | 比泥巴好過，但**會滑出去** —— 懲罰是打滑不是變慢 |
| **上坡** | 0.72 | 0.02 | 爬得慢 |
| **下坡** | 1.28 | 0.02 | 衝得快 |
| 加速帶 | 1.00 ＋ 0.60 | 0.02 | — |

上下坡一律**成對**放（先上後下）。倍率看起來對稱（±28%），但一對坡跑起來是
淨扣時間的：慢的那段待得久、快的那段一下就過去，平均速度是調和平均
`2/(1/0.72+1/1.28)` ＝ 0.92。要讓一對坡淨零得把下坡開到 1.64，那個速度進彎會直接飛出去。

**捷徑**的 `from`／`to` 一律從幾何重算，不信賽道資料裡寫的 —— 理由跟泥巴走
`ontoRoad` 一樣：賽道會被 `fitWiden`／`GROW` 放大，手寫的節點 index 對不上。
（原本三條手設捷徑全都寫錯，宣稱取代 336 單位的正路、本身卻有 966 單位長。）

### 機制與標誌的自動佈局

上下坡、水坑、捷徑、交通標誌全部由 `placeFeatures`／`placeSigns`
從幾何算出來，種子是賽道的 seed：

- 手設與隨機賽道**共用同一套邏輯**，不用寫兩份，新賽道自動就有
- 同一個 seed 一定長出一樣的東西（線上對戰兩邊要算出同一張）
- 賽道幾何一改，機制與標誌跟著改，不會指錯地方
- 賽道資料裡寫死 `slopes`／`water` 就整包以它為準

直線段放坡（放不下會整對消失），
彎道出口放水坑（那裡最需要抓地力）。找不到夠直的段就一路退讓：先縮短，
再放寬平均彎度 —— 沒有這個退讓，糖果餅乾、雪地那種整張都在轉的賽道一段都放不下。

**交通標誌**立在事件前 20 個節點（約兩秒的反應時間）的路邊：
左轉、右轉、連續彎、上坡、下坡、水坑六種。追尾視角看不到遠處的路型，
沒有標誌的話「前面是左彎還是右彎」只能靠背賽道。牌面永遠正面朝鏡頭 ——
真的把牌子轉向，斜著看就只剩一條線。牌子只立在草地上（窄又會折回來的賽道
右邊常常就是另一段路面），而且不會立在它要警告的那個東西上面。

標誌的左右是「投影到畫面之後」的左右，不是世界座標外積的左右 ——
這個投影讓世界 +y 落在畫面右邊，兩者是鏡像的。而且方向是從
**牌子最後站的位置**往前量（透視加權，近景權重高），不是從彎那邊算好再立牌：
牌子會被間距限制推移，推移之後前方那個彎可能已經換成別的了。

任兩塊牌子至少隔 28 個節點（約 390 單位，跑過去約 2.6 秒）。
每一種機制是各自挑位置的，所以不疏開的話不同種類會疊在一起 ——
連著三塊牌子閃過去，玩家一塊都讀不到。擠在一起時留「不知道代價最大」的那一種：
路型（連續彎、左右轉）> 水坑 > 上下坡。

目前 25 張賽道共 199 塊標誌（每張 4～12 塊）、80 段坡、77 個水坑、9 條捷徑。

### 追尾立體視角

畫面是真的透視投影：地面是 z = 0 的平面，東西靠高度抬起來，
`sx = halfW + r * focal / f`、`sy = horizon + (camZ - z) * focal / f`，由遠到近畫。

鏡頭**固定在自己身上**，而且只有一種模式（設定裡沒有鏡頭跟隨的選項）：
位置與偏航共用同一條軸線 `cam.h`，而 `cam.h` 就是**車頭角本身** ——
不看行進方向、不看前方賽道，所以鏡頭永遠不會自己轉，
畫面只有在你轉方向的時候才跟著轉。毛毛蟲永遠在畫面正中央、大小固定，
永遠最後畫、永遠不淡出。

`Render.headCamYaw` 做三件事。前兩件是為了「畫面是 60Hz」而不是為了跟隨：
一階濾波（`tau` 0.05 秒）把 30Hz 物理的階梯磨掉，再用已知的角速度 `turnVel`
做前饋（`lead` 0.055 秒）把濾波的落後抵銷回來。實測比直接抄車頭角還平順五倍、
落後還更小；把「車頭正前方的點」投影到畫面上，全程偏離中心不到畫面寬的 2%。

第三件是**轉速上限**（`maxRate` 1.20 rad/s ＝ 69°/s），只砍「急甩」那一下。
實際開起來車頭角速度的分布是中位 16°/s、九成 60°/s —— 一般過彎其實很慢，
是最上面那一成在甩。上限卡在九成之上：

| 情境 | 落後 | 尖峰轉速 |
| --- | --- | --- |
| 九成的彎（60°/s） | 1° | 不受限 |
| 0.4 秒急甩 | — | 101 → 73°/s |
| 滿舵長彎 | 19° | 不受限 |

上限不能再往下：訂 54°/s 的話連九成的彎都會落後 12°，一般過彎就看得出毛毛蟲歪掉。

### 畫面轉太快會暈，該調哪裡

**調鏡頭的轉速上限沒有用。** 實測上限從 54 降到 14°/s，持續過彎的尖峰只從
119 掉到 113°/s，落後卻從 25° 爆到 94°。原因是原理上的：彎要轉過去的總角度
由賽道決定，鏡頭遲早要轉完，不然就是愈落愈後面。限速只能改變「什麼時候轉」，
不能改變「轉多少」。

**真正有效而且零代價的是讓車本身轉慢一點**（`Rules.C.TURN`）——
鏡頭鎖在車頭上，車頭轉多快畫面就轉多快，車轉慢畫面就少轉，而鏡頭完全不用落後。
3.15 → 2.35 把高速時的最大轉速從 135°/s 降到 101°/s（少 25%），
二十五張賽道全部還跑得完，圈速幾乎不變。再往下到 2.10 就有一張賽道過不了彎。

（註：拿 AI 量整場的角速度分布看不出 `TURN` 的差別 ——
AI 會照走線把方向按久一點補回來。這個值真正影響的是「人急甩一下能轉多少」。）

毛毛蟲是**立起來**的：尾巴踩在地上，身體斜斜往上疊，頭在最上面，
頭上兩顆白色觸角球是從後面認得出頭的唯一線索。
身體**不做左右擺動、不做上下起伏、也不沿著走過的軌跡取樣** ——
那三件事在追尾視角下就是「在畫面裡抖」跟「拖著殘影」。
陰影與外框都是所有節合成同一條路徑只填一次，重疊處才不會疊出一圈一圈的殘影。

### 衝刺賽道（沒有圈數）

`open: true` 的賽道是一條開放路徑，不繞圈：起跑格排在路徑開頭，跑到最後幾個節點就完賽。
所有「節點索引 +N」的地方都改成 `Tracks.idx()` —— 環狀是繞回去，衝刺是夾在兩端。
不夾住的話，快到終點時「往前看 30 個節點」會看到起跑線，AI 會突然往回轉。
HUD 的圈數欄換成完成百分比，時間換成總時間；線上房主設幾圈都一樣是一趟。

### 分頁切走不會暫停

分頁一藏起來，`requestAnimationFrame` 就被瀏覽器停掉，單機等於整場凍住。
改成以 `performance.now()` 的真實時間推進，切走多久就補跑多久；
補跑有預算（一幀最多 2.5 秒，剩下的下一幀繼續），另外掛一支 250ms 的 timer，
分頁隱藏時靠它推進（背景 timer 被限制到一秒一次，但一次補一秒的量，結果一樣）。

### 自動畫質

每一幀量一次畫面時間，超過 23ms（約 43fps）就進低效能模式，
把純裝飾的東西關掉：地面顆粒、太陽光暈、雲、速度線、遠處的裝飾物；
回到 16.5ms 以下才升回來，兩個門檻做遲滯，才不會在邊界上一直開開關關。
天空與地面的漸層也改成快取，不再每一幀重建。

│       ├── config.js         全站唯一的 server URL 入口
│       ├── rng.js            可注入種子的亂數
│       ├── rules.js          ★ 共用規則核心（瀏覽器與伺服器同一份）
│       ├── tracks.js         賽道幾何、地形網格、檢查點、隨機生成
│       ├── items.js          六種道具與橡皮筋分配

│       ├── audio.js          程序化 BGM 與音效（不依賴外部音檔）
│       ├── net.js            WebSocket、預測與校正
│       ├── online.js         大廳、房間、觀戰、邀請、聊天
│       ├── app.js            畫面流程與主迴圈
│       └── themes/           八隻毛毛蟲、六套賽道配色、隨機暱稱（純資料）

## 部署

### 伺服器（Render 免費方案）

`render.yaml` 已經寫好。匯入 repo 之後：

- Build Command：留空（零依賴）
- Start Command：`node server.js`
- Health Check Path：`/health`
- 環境變數 `ALLOW_ORIGIN`：填前端網址，例如 `https://pjh-eric.github.io`

免費方案會休眠，第一個人進來要等 30～60 秒冷啟動，前端會顯示「伺服器可能在睡覺，正在叫醒它…」並自動重試。
房間狀態視為可清理的暫時狀態，不存磁碟，服務重啟不會留下垃圾。

### 前端（GitHub Pages）

`.github/workflows/pages.yml` 會在推到 `main` 時跑完整驗收再發佈。
先到 **Settings → Secrets and variables → Actions → Variables** 新增 `GAME_SERVER_URL`，
值填 Render 上的網址；建置時會由 `scripts/inject-server-url.js` 注入 `config.js`。

沒有設也能發，只是前端只能玩單機。

### server URL 規則

前端連線位置**只從 `public/js/config.js` 來**，解析優先序：

1. 網址參數 `?server=https://example.com`
2. 建置時注入的 `GAME_SERVER_URL`
3. 頁面本身就是伺服器發出來的 → 同源
4. 都沒有 → 只能玩單機

**不做 localhost 回退**，不寫死任何平台網址，秘密不進前端 bundle。
WebSocket 網址由 `Config.toWs()` 換算（http→ws、https→wss），不用字串替換猜協定。
